# Project Master Plan: Sage — Personal & Family Financial Intelligence Hub

A comprehensive personal and family financial intelligence system connecting **Monarch Money** to **Google BigQuery** and **Google Gemini Conversational Analytics** (`geminidataanalytics.googleapis.com`).

---

## 1. Executive Summary & Core Objectives

Monarch Money is the single source of truth and data aggregation hub (connecting to banks, credit cards, investments, and debt facilities via Plaid/MX). While Monarch tracks where money went, this system turns historical financial data into an **Active Financial Advisor and Debt Optimization Engine**.

### Core Objectives:
1. **Optimize Family Spend**: Distinguish non-negotiable family baseline expenses (mortgage, groceries, utilities, childcare) from discretionary variable leakage (dining out, delivery fees, retail impulse).
2. **Audit & Prune Subscriptions**: Automatically detect recurring debits, identify redundant overlapping services (streaming, cloud storage, memberships), and flag silent price creep.
3. **Budget Discipline & Pacing**: Enforce monthly envelope tracking using exact, deterministic GoogleSQL calculations in BigQuery.
4. **Accelerate HELOC Debt Paydown**: Model daily compound interest accrual on the HELOC balance and quantify the exact timeline and interest savings generated by sweeping discretionary savings into principal debt.

## 3. Data Model & Optimization Engines

### A. Raw Tables (`schema.sql`)
1. **`raw_accounts`**: Stores account balances, account type (`depository`, `credit`, `loan`), subtype (`checking`, `credit_card`, `heloc`), credit limits, and interest rates (e.g. `0.070` for 7.0% APR).
2. **`raw_transactions`**: Stores transaction records (`transaction_id`, `account_id`, `transaction_date`, `amount`, `merchant_name`, `clean_merchant_name`, `category_name`, `pending`).
3. **`raw_categories`**: Budget group hierarchy (`Fixed`, `Discretionary`, `Debt`, `Income`, `Transfer`).

### B. Analytical Views
- **`v_active_subscriptions`**: Automatically detects recurrence intervals (`MONTHLY`, `QUARTERLY`, `ANNUAL`), flags price creep (`has_price_increased`), and calculates annualized run rates.
- **`v_spend_classification`**: Monthly rollup distinguishing non-negotiable fixed family overhead from discretionary variable leakage.
- **`v_heloc_daily_cost`**: Models the average daily balance interest burden (`(current_balance * apr) / 365`) and interest saved per $500 monthly principal reduction.
- **`v_food_efficiency`**: Computes the percentage of food spend going to dining out and delivery markups (DoorDash, UberEats) vs. grocery meal preparation.
- **`v_micro_transaction_leakage`**: Isolates frequent transactions under $35 occurring with high cadence to show annualized run rates of small habits.
- **`v_subscription_overlap`**: Groups active subscriptions by category (e.g. multiple streaming services, duplicate cloud storage) to flag redundancy.

## 4. Spend Optimization Framework

The Conversational Analytics agent operates on a **3-Tier Spend Reduction & Debt Acceleration Framework**:

### Tier 1: Painless Cuts (Zero Lifestyle Impact)
- **Target**: Redundant streaming services, duplicate cloud storage, dormant memberships, and services with recent price hikes.
- **Action**: Subscription rotation (keep 1-2 active services per season) and immediate cancellation of unused subscriptions.

### Tier 2: High-Leverage Habit Rebalancing
- **Target**: Food delivery service fees, convenience store runs, impulse micro-transactions (< $35).
- **Action**: Capping delivery orders (shifting 2 meals/month to home cooking), establishing weekly allowances for coffee/snacks.

### Tier 3: HELOC Debt Acceleration (The Payoff Multiplier)
- **Target**: HELOC average daily balance.
- **Action**: Every dollar liberated from Tiers 1 & 2 is modeled as an immediate principal sweep into the HELOC:
  $$\text{Daily Interest Saved} = \frac{\Delta \text{Principal} \times \text{APR}}{365}$$
  $$\text{Annual Compound Interest Saved} = \Delta \text{Principal} \times \text{APR}$$
- **Impact**: Quantifies months shaved off debt freedom and thousands in lifetime interest saved.

## 6. How to Update Over Time (The Lifecycle Workflow)

### Scenario A: Updating Application Code, Models, or System Prompts
Whenever you tweak `main.py`, `requirements.txt`, or agent behavior:
```bash
# Run one command from your machine:
gcloud builds submit --config=cloudbuild.yaml --project="$PROJECT_ID"
```
* **What happens**: Cloud Build builds the image, pushes to Artifact Registry, deploys a zero-downtime revision to Cloud Run, and tests `/health`.

### Scenario B: Adding New Analytical Views or Metrics to BigQuery
Whenever you add a new SQL view in `schema.sql` (e.g. vacation savings, tax projections, or car loan payoff models):
```bash
# Simply submit the build:
gcloud builds submit --config=cloudbuild.yaml --project="$PROJECT_ID"
```
* **What happens**: Step 4 of `cloudbuild.yaml` automatically re-applies `schema.sql` against `family_finance` in BigQuery without touching Terraform.

### Scenario C: Infrastructure or IAM Changes
Whenever you add new GCP APIs, change regions, or alter permissions:
```bash
cd terraform
terraform apply
```
